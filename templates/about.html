작동 방식

이 앱은 고객 문의 하나를 다섯 단계로 처리합니다. 모든 단계는 Microsoft Agent Framework의 순차 워크플로 하나로 연결되고, 모델 연결은 GitHub Copilot SDK를 씁니다.

처리 단계

  1. 사전 점검 (코드) 문의 속 전화번호·이메일·카드번호·계좌번호·주민등록번호를 가리고, "이전 지시 무시" 같은 지시문 표현을 찾아 표시합니다.
  2. 분류 에이전트 문의 유형(배송·환불·교환·기타), 불만도(1~5), 핵심 요청을 판단합니다.
  3. 조사 에이전트 도구로 주문 정보, 정책 조항, 같은 주문의 이전 문의를 직접 조회하고 확인된 사실만 정리합니다.
  4. 답변 에이전트 확인된 사실만으로 답장 초안을 쓰고 문장마다 근거를 답니다. 환불은 실행하지 않고 제안만 합니다.
  5. 근거 검증 (코드) 답장의 금액·날짜·기간·상태·정책 조항을 실제 조회 결과와 대조하고, 근거가 없는 문장을 표시합니다.

에이전트가 쓸 수 있는 도구

  • 주문 조회 현재 문의의 주문만 조회합니다. 다른 주문번호는 거부합니다.
  • 정책 검색 환불·교환·배송 정책 조항을 찾습니다.
  • 이전 문의 조회 같은 주문으로 들어온 이전 문의와 처리 결과를 확인합니다.

이 세 도구 외의 권한 요청(명령 실행, 파일 읽기·쓰기 등)은 모두 거부합니다.

사람이 결정하는 일

  • 답장은 운영자가 고친 뒤 확정합니다. 근거 없는 문장이 남아 있으면 확인 체크를 해야 확정됩니다.
  • 환불은 AI가 제안만 하고, 운영자가 승인해야 처리됩니다.

데이터 처리

  • 개인정보는 AI에 보내기 전에 가리고, 가린 내용만 저장합니다. 로그에는 문의 원문과 연락처를 남기지 않습니다.
  • 로그인 없이 쓰는 공개 데모라서 브라우저마다 작업 공간을 따로 둡니다. 다른 사람의 문의는 보이지 않습니다.
  • 문의 기록은 {{ retention }}시간이 지나면 자동으로 지웁니다.
  • 남용을 막기 위해 브라우저당 한 시간에 {{ limit }}건까지 처리합니다.
  • 서버의 비밀 값은 Azure Key Vault에 두고, 앱은 Managed Identity로만 접근합니다.

한계

  • AI가 만든 초안은 틀릴 수 있습니다. 근거 검증은 금액·날짜 같은 확인 가능한 사실만 대조하며, 문장의 뜻까지 보장하지는 않습니다.
  • 지시문 탐지는 알려진 표현을 기준으로 하므로 모든 공격을 막지는 못합니다. 그래서 위험한 처리는 항상 사람이 결정합니다.
